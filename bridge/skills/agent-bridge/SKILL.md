# 使用协同桥

本 Skill 目录的 `../../bridge.py` 是运行器，`../../README.md` 是项目说明。先读项目说明；不要假定此 Skill 已安装到全局，单独复制 Skill 文件不会带上运行器。

目标是让 Codex 指挥一个可独立验收的任务，并把退出码、实际文件改动和失败证据交给用户。默认串行；没有用户明确要求就不创建子代理或改为团队运行。

1. 了解真实仓库和文件上下文，建立 `schemas/task.schema.json` 对应的契约。只列此次允许修改的文件；文件夹权限用末尾 `/` 明示。输入文件用 `input_refs` 固定哈希。
2. `submit` 只记录任务；`plan` 只读核对基线、依赖、入口并给出批准哈希。不要把这两步称为已执行任务。
3. 模型任务运行前，说明具体执行器、工作区、模型选择、预计作用范围和进程控制影响，取得针对该计划的明确批准。执行使用实际 `plan_sha256`；不可填假值或自动代用户批准。
4. 原生请求层节流和步数尚未实证。`--ack-unmetered` 表示用户明确知悉这个限制，不代表已经限制请求。没有这种确认不能启动。默认未自动测试，不调用探测脚本，不切换 CC Switch 当前供应商。
5. 新前端默认 OpenCode `opencode_mode: "shared"`。`prepare` 按计划创建 worktree 与原生空会话；先确认真实客户端在同一服务、同一工作区可见，再 `run --confirm-visible` 发送提示词。桥只控制本任务新会话，不自动降级为 standalone。旧契约缺省 standalone；DSH 保留 headless `--json`。不改 Console 工作区连接、认证或模型配置。
6. 查看 `result.json`、日志、前后哈希和 workspace 中的真实产物。只读审查后交用户手动验证；模型的“完成”及退出 0 都不能代替验收。
   **真实执行验收规则：** 构建后若假执行器／模拟无法证明目标行为，必须安排最小范围的真实执行器任务验收；模拟结果只能标记为辅助验证，不能替代真实链路。开始真实任务前，明确执行器、实际配置读取路径、模型/供应商、仓库与允许修改文件、产物、预计请求和额度不确定性、进程影响，并取得针对该范围的用户明确批准。使用干净的一次性 Git fixture 或经用户批准的真实仓库；不得把模拟生成的产物写成真实执行证据。遇到 429 立即停止并至少冷却 5 分钟；不自动重试。
7. 有问题，报告真实错误并用 `revise` 形成新版本；不在旧 worktree 重派，不覆盖旧结果，不擅自清理目录。取消须指定当前 attempt_id。共享模式先向该会话 interrupt，再关闭本次 CLI 观察进程，不关闭后台服务；未确认原生 idle 时 BLOCKED，不重派。授权已经明确且覆盖当前具体范围时沿用，不重复索要。
8. `review --decision accept` 是用户人工接收操作，必须附只读审计与用户真实路径证据。桥只检查证据存在、哈希和机器一致性；内容真实性仍由审计及用户确认。

不要输出密钥、JWT 或原始配置字符串。若日志脱敏不足，停止传播日志并报告，不用“配置只读”解释泄漏。

关于协议、版本、权限或运行路径的缺口，用 BLOCKED 和所需证据说明，不填想象中的成功。不要自动启动 UI、浏览器、服务或修改系统设置。

共享模式记录 native-session.json、prompt-intent.json、原生错误和工具警告；发送状态不明不得重发。前端只读“回读原生状态”不发送模型请求，也不代替真实 GUI 验收。`/api/runtime` 给出启动时实际加载哈希与 store。已准备会话禁止修订，现场不自动删除。
