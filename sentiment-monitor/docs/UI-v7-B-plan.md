## 3. 存储与生命周期

### 3.1 观察周期

- 观察对象必须是已存在于 `p1_evidence` 的身份：以该表既有 `identity_key` 作为唯一同帖身份；不得按标题相似度归并。API 调用端用 `evidence_id` 指定目标，由后端解析身份，不让浏览器提交 identity 或任意 URL。
- 新增单独的观察周期表（建议 `p1_watch_periods`），一行表示一次显式加入周期，至少包含随机 `watch_id`、`identity_key`、加入时刻、24h 到期时刻、加入原因、显式退出时刻/原因。周期行只追加，不删除，不因退出/到期而移除任何证据或历史。字段与建表名最终固定在实现说明中。
- 活跃资格：未显式退出且服务器当前 UTC 时刻早于 `expires_at`。状态在读取时根据真实 UTC 时钟推导为 `active` / `expired` / `exited`；到期不是后台任务，不自动续期、不触发来源访问，也不必通过 GET 偷写“过期事件”。首次/最近观测从 `p1_evidence` 按身份真实历史计算；加入/退出时刻由服务器生成 UTC 时间，加入时刻与首次观测时刻是不同概念。
- 显式重新加入已退出或过期身份允许建立新周期，并保留旧周期历史；已有未过期活跃周期再次加入返回冲突，不延长其 24h。任何时候最多 3 个活跃周期；达到上限必须原子拒绝，不能静默扩容。P1 全库 3 身份上限继续有效，TopK 的 1/2/3 展示不影响观察资格。
- 加入和退出原因是人工填写的短文本（建议 1–200 字符）；不包含凭据、评论/回复正文或自动判断。手动退出不撤销/删改 observation。

### 3.2 同帖真实观测与比较规则

- 历史点直接来自 `p1_evidence` 的 append 记录，不另建爬虫、定时任务或伪造历史表。`p1_import()` 继续是人工已取证导入入口；同身份新 observation 形成新快照时自然追加。完全相同 snapshot 重放仍按既有规则去重。
- `observed_at` 使用后端现有严格带时区校验并归一 UTC；每个返回点同时保留原始 `observed_raw`，展示可用本地化时间，但排序和间隔计算只用归一 UTC 的真实观测时间。日期筛选含时区，语义是观测时间，不是发布时间、导入时间或系统抓取时间。
- 同身份同 UTC 时刻、同精确计数、同 `source_field` 的重复观测可在比较序列中合并成一个时间桶，返回其证据引用数量/IDs，不能重复累计或制造额外速率；底层 P1 证据行仍保留。若同一时刻不同计数，整个该时间桶标 `same_time_conflict`，其中点不可比较/不出速率；后续点不能跨过冲突桶借用更早的值。
- 仅当相邻有效时间桶两端都是非负整数 `exact`，且 `comment_count.source_field` 口径一致，才比较。`unknown` / `approximate` 不补 0，不参与数值比较；口径变化标 `source_changed`，不比较。缺少前一有效点标 `single_point` / `waiting_for_second_point`。
- 真实时间间隔 `seconds > 0` 时，计数变化率按 `delta * 3600 / seconds`（条/小时）计算，保留足够精度并在 UI 格式化；30/60 分钟间隔按各自真实秒数归一。两点相同计数是有效的 0 速率。计数减少要标明 `retraction`/回撤并显示负变化（不得描述为增长）；出现零或负间隔不计算速率并报告时间异常。
- 比较状态是可解释的数据质量标签，不是情绪、因果、群体或事件判断。后端先在完整有序历史上判定比较，再应用显示日期窗口；窗口首点若速率依赖窗口外的真实前点，允许展示该真实区间和间隔，必须清楚标示，不得把截断点伪装成单点/零值。

## 4. API 契约草案

所有路径同源本机回环；任何写请求复用现有严格 `Origin == http://127.0.0.1:8790` 且 `Host == 127.0.0.1:8790` 校验及写锁。读取路径只从本地 DB 读，不请求帖子 URL。JSON 字段精确校验，拒绝额外字段；业务 DOM 不显示 `identity_key`、快照/hash/path、API 路径或日志。

### 4.1 `GET /api/p1/watchlist`

无请求体。返回 `{schema_version, active_limit:3, active:[...], history:[...]}`。`active` 按最近观测时间倒序，最多 3 个活跃周期；`history` 是所有观察周期（含过期/退出），按加入时间倒序。每项包含：

```json
{
  "watch_id": "opaque-id",
  "evidence_id": "当前可用的 P1 证据 ID",
  "title": "原标题",
  "url": "原帖原地址",
  "source_name": "来源",
  "status": "active|expired|exited",
  "entered_at": "UTC ISO-8601",
  "expires_at": "UTC ISO-8601",
  "entry_reason": "人工加入原因",
  "exited_at": null,
  "exit_reason": null,
  "first_observed_at": "UTC ISO-8601 或 null",
  "latest_observed_at": "UTC ISO-8601 或 null"
}
```

`evidence_id` 使用该身份最近真实证据行，不能因 TopK 排名变化而变化身份。完整观察周期供管理操作与历史展示；业务 UI 只渲染标题、来源、链接、观测/生命周期时间、计数和原因，不渲染内部 ID。空库返回空数组。

### 4.2 `POST /api/p1/watchlist`

请求体只能是 `{ "evidence_id": "...", "reason": "人工填写" }`。服务端查证 evidence 存在、解析身份、在单个写事务内检查活跃重复和 3 周期上限，并用服务端 UTC now 创建 24h 周期。成功 `201` 返回 `{ "watch": <周期项> }`。不得请求该 evidence 的 URL。

### 4.3 `POST /api/p1/watchlist/exit`

请求体只能是 `{ "watch_id": "...", "reason": "人工填写" }`。仅对当前 active 周期记录退出时刻/原因；成功 `200` 返回 `{ "watch": <周期项 status=exited> }`。退出是历史追加/状态转换，不删除周期和证据。

### 4.4 `GET /api/p1/history`

查询字段：必需 `evidence_id`，可选 `from` / `to`（带时区 ISO-8601，`from` 含、`to` 不含）、`limit`（默认 500，范围 1–500）、`offset`（默认 0，非负整数）。不允许重复 query key、空值或无时区时间。先解析当前或历史 `evidence_id` 对应 identity，再对该 identity 历史点排序、比较和筛选；仅当证据不存在返回 404。响应为：

```json
{
  "evidence_id": "请求引用",
  "filter": {"from": null, "to": null, "time_basis": "observed_at"},
  "points": [{
    "evidence_ids": ["p1 evidence IDs"],
    "observed_at": "UTC ISO-8601",
    "observed_raw": "原始带时区字符串",
    "comment_count": {"value": 522, "precision": "exact", "source_field": "stat.reply"},
    "interval_seconds": null,
    "delta": null,
    "rate_per_hour": null,
    "comparison": "single_point|comparable|same_time_conflict|unknown|approximate|source_changed|retraction|invalid_interval"
  }],
  "limit": 500,
  "offset": 0,
  "has_more": false
}
```

内部 `source_field` 只供一致口径判断和测试；UI 显示现有中文业务来源描述，不回显平台字段名。分页顺序必须稳定（UTC 时刻、导入时刻、证据 ID）；`has_more` 为真时 UI 继续请求，不把截断历史称为完整历史。`from/to` 对点集筛选，但比较仍使用筛选窗口外紧邻的真实前点作为区间基准。

### 4.5 状态码

| 状态码 | 语义 |
| --- | --- |
| `200` | 读取成功或退出成功。 |
| `201` | 新观察周期创建成功。 |
| `400` | JSON/query 格式、缺字段/多字段、重复参数或时区格式非法。 |
| `403` | 写请求 Origin/Host 非既有严格同源值。 |
| `404` | evidence_id/watch_id 不存在。 |
| `409` | 已存在活跃周期、目标周期已退出/过期，或活跃观察上限已满；错误 JSON 明确原因，原状态不变。 |
| `422` | reason/evidence_id 等字段类型或业务约束不合法。 |
| `500` | SQLite/文件等实际存储异常；不返回成功形状、不吞错。 |

错误体沿用 `{ "error": "可读原因", "status": "rejected|failed" }`（适用时）；`app.js` 写入失败须清除过期业务缓存并只给业务短提示。接口不得包含日志、异常栈或凭据。

## 5. UI、TopK 与筛选语义

- 先实现并核验 API，再增加主导航“观察清单”；不把不存在的 API 预先画成可用入口。保留固定“议题与表达线索”标题、弱数据管理入口和现有 A 布局。观察清单为独立业务面板，不占用议题页 TopK，也不把 watchlist=TopK。
- P1 候选身份全局上限仍是 3；TopK 展示控制仍是 1/2/3 且默认 3，只改变排名展示。观察清单是人工选择的身份子集，活跃上限 3。帖子掉出 Top2/Top3 后仍可留在观察清单并按人工导入继续增加真实观测；未入清单身份不自动抓取或轮询。
- 每个活跃观察项显示原帖标题/来源、人工加入原因、真实加入时刻、首次/最近观测、24h 到期倒计时/到期状态、退出操作；退出历史与到期项可查。加入/退出不会触发采集、删除证据或自动续期。时间到期只表示观察资格结束，不是请求授权。
- 使用 ECharts 分别绘制**累计评论计数**与**每小时变化率**两张图（建议每帖独立小图/可选帖切换，不跨身份聚合）；一个图不叠另一指标。展示精确/约数/未知、原始观测时刻、实际间隔、回撤/同刻冲突/口径变化等状态；缺测不补 0，单点明确等待第二点。无 JS/无库/错误时提供短状态和可读数据表，不留下大块空白。
- 统一日期筛选放入总览、议题、检索共用的筛选状态与控件；`from/to` 表示 `observed_at` 区间。载入最多 3 个 P1 identity 后，按每个身份请求历史窗口，并取窗口内最新真实点作为该窗口下该帖的唯一候选快照；无窗口匹配点的身份不进入符合范围的分子。三视图必须从同一份窗口候选集合生成列表、计数分母、精确排序与 TopK，页面说明全体候选数、符合日期范围数和当前其他筛选数；不再显示“这是单点不是观察清单”的旧假状态。日期范围内没有该帖观测时不以范围外最新值冒充范围内结果。watchlist 图表也服从同一日期窗口，生命周期状态仍按当前服务器时间解释。
- 对概览、历史、观察清单请求使用递增令牌/取消旧请求，失败后清掉旧结果，避免快速切换窗口留下旧图或旧分母。业务 DOM 和图表 tooltip 只显示业务数据与必要边界提示，不生成快照/raw/hash/path/API 字段、错误原文或执行日志节点。原地址继续使用既有安全链接呈现，不用于 fetch。
