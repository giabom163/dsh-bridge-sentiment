## 有作用即实机验收（用户明确要求，2026-10-16）

- 用户指令：“涉及作用的自己实机验收，这点加入项目规则。”
- **任何会产生实际作用的改动，执行者必须自己实机验收后才能结案**：写仓库或产物、改契约、发布、采集、启停服务、改配置、动模型或提示词，一律不得只凭静态检查（语法检查、AST、单测、类型检查、读代码）宣布完成。
- 静态检查通过 ≠ 功能可用。必须留下真实运行证据，按对象取用：
  1. **界面/前端** → 真浏览器打开（用本机已装 Chrome，`channel:chrome`，不新下载 Chromium），走一遍用户路径，留截图 + DOM/尺寸读数 + 控制台错误数与失败请求数；
  2. **CLI / 桥 / 服务** → 真跑一次命令或任务，贴真实退出码与 stdout/stderr；桥任务另附四轴与 `native_cost` 回读；
  3. **采集 / 抓取 / 适配器** → 真跑目标适配器，记录真实返回（条数 + 样例字段）或真实错误码与原文；`strategy: public` 不等于不依赖浏览器桥，必须逐个实跑确认；
  4. **模型 / 提示词** → 真调一次并回读 token、延迟、JSON 合法性；只做静态审阅不算验证；
  5. **配置 / 环境** → 真读回生效值（进程命令行、端口归属、文件哈希、加载到的扩展），不采信“我改过了”。
- 结论必须显式分列“已验证 / 未验证”；未验证项不得写 PASS。无法实机验收时记录真实阻断原因（例如审批在会话内被禁用、Chrome 155 已禁用 `--load-extension`），不得用静态检查充当验收。
- 反面案例（2026-10-16）：控制台详情面板因 `chip is not defined` 整体不渲染，而 `node --check`、AST 与单元自测全绿；真浏览器一眼抓到。正面案例：`opencli toutiao hot` 实跑成功（10 条），而同为 public 的 `tieba hot`/`36kr hot`/`aibase news` 实跑报 `BROWSER_CONNECT: extension not connected`——只有实跑能区分。
